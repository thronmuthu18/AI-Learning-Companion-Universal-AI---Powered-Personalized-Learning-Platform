# RISK REGISTER — AI Learning Companion

| ID | Risk | Severity | Likelihood | Mitigation & Current Status |
|---|---|---|---|---|
| RSK-01 | **macOS / Xcode Unavailable on Windows Host** — Cannot compile iOS `.xcworkspace`/`.ipa` or test physical iPhone ExecuTorch inference locally. | High | Certain | Implemented complete Swift `ExecuTorchLlamaModule`, `ExecuTorchLlama.podspec`, and `withExecuTorchNative.js` SPM plugin; documented exact macOS build steps in `BUILD_AND_RUNBOOK.md` and marked iOS build/device criteria `BLOCKED` (BLK-01). |
| RSK-02 | **Android SDK & Physical Device Absence** — `ANDROID_HOME` unset and no USB ADB device attached; installing SDK requires user license approval. | High | High | Ran `expo prebuild --platform android` to verify Gradle project & autolinking; awaiting user approval to install Android SDK on `M:\Android\Sdk` (BLK-03). |
| RSK-03 | **Gated Llama 3.2 Weights (`HF_TOKEN`)** — `meta-llama/Llama-3.2-1B-Instruct` requires user account & Meta license acceptance before exporting `.pte`. | High | Certain | Created reproducible `export_llama_executorch.py` + `verify_model_integrity.py` + in-app `.pte`/`tokenizer.model` picker; WebLLM uses public MLC weights for browser verification (BLK-02). |
| RSK-04 | **Tamil Language Quality in Stock Llama 3.2 1B** — Meta officially supports 8 languages (English, German, French, Italian, Portuguese, Spanish, Hindi, Thai); Tamil is not officially supported. | Medium | High | Documented tokenization overhead & English code-switching risks in `MODEL_DEPLOYMENT_PLAN.md`; UI defaults to English prompts/structured JSON while noting future Tamil-adapted LoRA/fine-tune support. |
| RSK-05 | **WebGPU / `shader-f16` Hardware Variance** — Older browsers or GPUs may lack WebGPU or `shader-f16`. | Medium | Medium | Implemented `detectWebGPUCapabilities()` checking `navigator.gpu`, adapter availability, and `shader-f16`, falling back automatically from `q4f16_1` to `q4f32_1`, or surfacing explicit unsupported error without cloud fallback. |
| RSK-06 | **Mobile RAM Pressure / OOM During `.pte` Load** — Loading 1B–3B weights on low-RAM phones can trigger OOM kills. | High | Medium | Selected 1B 4-bit XNNPACK (`LOAD_MODE_MMAP`, `android:largeHeap="true"`) as primary mobile config (~1–2 GB peak RAM), reserving 3B for >= 4 GB VRAM/high-RAM targets. |
| RSK-07 | **Cross-Runtime Artifact Mismatch** — ExecuTorch `.pte` files do not run on WebLLM, and MLC WebGPU weights do not run on ExecuTorch. | Low | Low | Enforced strict separation in `ai/model-config/models.json`, `LocalAIProvider` adapters, and documentation. |
| RSK-08 | **Live Chrome Browser Verification Blocked** — Chrome remote debugging (`DevToolsActivePort`) not enabled on host. | Medium | Medium | Vite production build (`apps/web/dist`) verified; user can enable `chrome://inspect/#remote-debugging` or test locally via `npm run web:preview` (BLK-04). |
